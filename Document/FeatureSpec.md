## 0. 핵심 결정 요약

| # | 항목 | 결정 |
|---|---|---|
| 1 | 게스트 모드 | 없음 — 회원가입 필수 |
| 2 | 회원가입 방식 | 아이디 기반 (이메일 인증 폐기, 소셜 연동 나중) |
| 3 | 데일리 팝업 문항 | 2문제 — 영어→한국어 1, 한국어→영어 1 |

| 5 | 카테고리 필터 | 안 만듦 + 풀이 화면에 메타 라벨(카테고리·난이도) 노출 금지 |

| 7 | 비번 복구 | 가입 시 이메일·전화번호·통신사 선택 입력으로 저장. 넣은 사람만 복구 |

활성 학습 기능: **데일리 팝업 + 문장 해석** 2가지.
지원 기능: **회원가입 + 로그인 + 학업 성취도**.

## 기능 1. 회원가입

### 화면 구성 (signup.html)
| 요소 | 종류 | 비고 |
|---|---|---|
| 아이디 | 텍스트 입력 | 중복 체크 대상 |
| 비밀번호 | 비밀번호 입력 | |
| 비밀번호 확인 | 비밀번호 입력 | 일치 검증 |
| 닉네임 | 텍스트 입력 | 화면 표시명 |
| 이메일 | 텍스트 입력 (선택) | 비번 복구용 |
| 전화번호 | 텍스트 입력 (선택) | 저장만 |
| 통신사 | 드롭다운 (선택) | SKT / KT / LG U+ / 알뜰폰 |
| 약관 동의 | 체크박스 (필수) | 이용약관 + 개인정보처리방침 |
| 회원가입 버튼 / 로그인 링크 | 버튼 / 링크 | |

### 입력 검증 규칙
- **아이디**: 4~20자, 영문 소문자+숫자+언더스코어, 중복 불가
- **비밀번호**: 8자 이상, 영문+숫자 조합 권장
- **비밀번호 확인**: 비밀번호와 완전 일치
- **닉네임**: 2~16자
- **이메일**: 입력 시 형식 검증(`x@y.z`), 빈 값 허용
- **전화번호**: 입력 시 숫자·하이픈만, 빈 값 허용
- **약관**: 필수 동의 — 미동의 시 버튼 비활성

### 사용자 흐름
1. 앱 최초 실행 → 로그인 화면 → "회원가입" 링크
2. 폼 작성 → 아이디 입력란 blur 시 중복 체크
3. "회원가입" 클릭 → 전체 검증 통과 시 진행
4. Supabase Auth 에 `{아이디}@mogugeo.local` + 비밀번호로 가입
5. 가입 직후 자동 생성: `User`(username·displayName·recoveryEmail·phone·carrier) + `UserSettings`(기본값) + `Streak`(0 초기화)
6. 성공 → 로그인 화면으로 이동 (또는 자동 로그인 → 난이도 선택)

### 엣지 케이스
- 아이디 중복 → 입력란 하단 인라인 에러, 제출 차단
- 네트워크 실패 → "잠시 후 다시 시도해주세요" + 입력값 보존
- 비번 불일치 → 확인란 인라인 에러
- 가입 도중 앱 종료 → auth.users 만 생기고 User row 누락 가능 → 다음 로그인 시 누락 row 보정 로직 필요

### 제약
- 게스트 모드 없음 — 가입해야 앱 사용 가능
- 소셜 로그인(네이버·카카오)은 이번 범위 제외

## 기능 2. 로그인

### 화면 구성 (main.html — 460×615 프레임리스)
| 요소 | 종류 |
|---|---|
| 아이디 / 비밀번호 | 텍스트·비밀번호 입력 |
| 자동 로그인 유지 | 체크박스 |
| 로그인 버튼 | 버튼 |
| 회원가입 링크 / 비밀번호 찾기 링크 | 링크 |

### 사용자 흐름
1. 아이디·비밀번호 입력
2. "로그인" → `{아이디}@mogugeo.local` 로 Supabase Auth `signInWithPassword`
3. **성공**:
   - `LoginLog` 기록 (시각·IP·디바이스·success=true)
   - 자동 로그인 체크 시 refresh token → Electron `safeStorage`
   - **`UserSettings.difficulty` 미설정이면** → 난이도 선택 화면(최초 1회) → 저장
   - 창 1180×860 확장 → 대시보드
4. **실패**:
   - `LoginLog` 기록 (success=false)
   - "아이디 또는 비밀번호가 올바르지 않습니다" — **어느 쪽이 틀렸는지 노출 안 함**(보안)

### 비밀번호 찾기
- `recoveryEmail` 등록자: 이메일 입력 → 일치 확인 → Supabase 재설정 링크 발송 (무료 SMTP 한도 내)
- 미등록자: "복구 이메일이 등록되어 있지 않습니다. 관리자에게 문의하세요" 안내

### 엣지 케이스
- 자동 로그인 토큰 만료 → 조용히 로그인 화면으로
- 오프라인 → "인터넷 연결이 필요합니다" (P2 부터 인증은 서버 필수)
- 연속 로그인 실패 → 이번 범위에선 잠금 없음 (로그만 누적)

## 기능 3. 데일리 팝업 ⭐

### 3-1. 스케줄링 — 앱 실행 여부와 무관

두 기능을 **분리**한다:

| 기능 | 수단 | 사용자 제어 |
|---|---|---|
| ① 부팅 시 트레이 상주 | `app.setLoginItemSettings` (또는 레지스트리 Run 키) | on/off |
| ② 정시 팝업 | **Windows Task Scheduler** (`schtasks`) | on/off + 시각 |

**Task Scheduler 작업 정의**
| 항목 | 값 |
|---|---|
| 작업명 | `MoGugeo Daily Popup` |
| 트리거 | 매일 `HH:MM` (사용자 설정값) |
| 동작 | `MoGugeo.exe --popup` |
| 옵션 | "예약 시간 놓친 작업을 가능한 한 빨리 실행" 켬 |
| 생성/갱신 시점 | 앱 설치 시, 설정에서 시각·on/off 변경 시 `schtasks` 호출 |
| 해제 | 설정에서 끄면 `schtasks /delete` |

**`--popup` 인자 분기 (main.ts 신설 필요)**
- `process.argv` 에 `--popup` 포함 시 → 메인 창 생략, 팝업 창만 생성, 트레이는 띄움
- 미포함(일반 실행) → 기존 로그인/메인 흐름

### 3-2. 팝업 창 구성 (520×700, alwaysOnTop, 단일 인스턴스)
- 헤더: 인사말 + 닫기/최소화
- **과제 1 (영어→한국어)**: 영어 문장 표시 → 한국어 입력란
- **과제 2 (한국어→영어)**: 한국어 문장 표시 → 영어 입력란
- "정답 확인" 버튼
- 결과 영역 (제출 후 노출): 각 문제 정답/오답 + 모범답안
- "대시보드로 이동" 링크
- 푸터: 스트릭 표시

### 3-3. 문제 선정 알고리즘
```
1순위: ReviewItem 중 nextReviewAt <= 현재 → due 항목 우선
2순위: StudyRecord 에 없는 미학습 문장 중 난이도 일치 → 랜덤
3순위: (다 풀었으면) 과거 정답률 낮았던 문장 재출제
※ 과제 1·2 는 서로 다른 문장
```

### 3-4. 채점 & 기록
- "정답 확인" → 두 입력란 채워졌는지 검증 (빈 칸 → 인라인 에러)
- 각 문제 채점 (문장 해석과 **동일 채점 로직 공유**)
- 결과 표시 + `StudyRecord` 2건 기록 (contentType=sentence)
- 틀린 문제 → `ReviewItem` 추가/갱신 (level 0)
- `Streak` 갱신
- **하루 1회 가드**: `lastPopupDate == 오늘` 이면 제출 차단, "오늘은 이미 완료했어요" 화면

### 3-5. 사용자 설정 항목
| 설정 | 값 | 기본 |
|---|---|---|
| 데일리 팝업 사용 | on/off | on |
| 팝업 시각 | HH:MM | 08:30 |
| 부팅 시 트레이 상주 | on/off | on |

요일 선택은 이번 범위 제외 (매일 고정).

### 3-6. 현재 코드 대비 미구현
- 정시 자동 트리거(스케줄러) 없음 — 현재 트레이 메뉴 수동 호출만
- `--popup` 인자 분기 없음
- 실제 채점 없음 — 입력만 채우면 통과
- 문제 하드코딩 — 콘텐츠 미연동
- 하루 1회 가드 없음

## 기능 4. 문장 해석

### 화면 구성 (sentence.html)
| 영역 | 요소 |
|---|---|
| 진행도 | 일일 목표 진행 바 + "N/M 문장" |
| 문장 카드 | 영어 문장 + 발음 버튼(TTS) + 해석 입력 textarea + "해석 확인" 버튼 |
| 피드백 섹션 (제출 후) | 모범답안 · 원어민 팁 · 문법 포인트 · 부가 설명 |
| 하단 액션 | "복습 리스트에 추가" · "다음 문장" |

### 사용자 흐름
1. 진입 → `UserSettings.difficulty` 에 맞는 문장 1개 로드 (**카테고리·난이도 라벨 노출 안 함**)
2. 영어 문장 표시, 발음 버튼으로 TTS 재생 가능
3. 해석 입력 → "해석 확인"
4. 채점 → 점수 산출 → 피드백 섹션 노출
5. 점수 ≥ 60 → 정답 처리(`sentenceCorrect++`), 입력란 초록 / 미만 → 빨강
6. `StudyRecord` 기록, 오답이면 `ReviewItem` 자동 추가
7. "다음 문장" → 새 문장 / "복습 추가" → 수동 `ReviewItem`

### 채점 로직 (현재 단순 키워드 매칭 → 개선안)
```
점수 = 키워드 매칭 40% + 토큰 유사도 60% + 형태소 어간 보너스
- 키워드: data.keywords 중 사용자 답에 포함된 비율
- 토큰 유사도: 정답·사용자답 띄어쓰기 토큰 일치 비율
- 형태소 보너스: 종결어미 제거 후 어간 일치 시 가산
- 결과: 0~100 정수, 합격선 60
```

### 상태별 화면
- **로딩**: 콘텐츠 로드 중 스피너
- **빈 상태**: 난이도 내 문장 소진 → "이 난이도 문장을 모두 학습했어요" + 복습 모드 제안
- **피드백 전/후**: 피드백 섹션 display 토글

### 엣지 케이스
- 빈 입력 제출 → 인라인 에러, 채점 안 함
- 채점 후 재제출 시도 → `answered` 플래그로 차단
- 콘텐츠 로드 실패 → 로컬 캐시 폴백

## 기능 5. 학업 성취도

### 화면 구성 (mypage.html — 현재 목업 → 실데이터 교체)
| 영역 | 요소 | 데이터 출처 |
|---|---|---|
| 프로필 헤더 | 닉네임 + 총 학습일 (**레벨 표시 제거**) | `User`, `StudyRecord` |
| 스트릭 카드 | 현재 연속일 + 최장 연속일 | `Streak` |
| 정확도 분석 | 최근 7일 일별 정답률 막대 차트 | `StudyRecord` 집계 |
| 학습 빈도 | 최근 N주 히트맵 | `StudyRecord` group by date |
| 복습 큐 현황 | 대기 항목 수 + 바로가기 | `ReviewItem` |
| 계정 관리 | 다크모드 토글 · 난이도 변경 · 로그아웃 | `UserSettings` |

### 데이터 집계 정의
- **현재 연속일**: `Streak.currentStreak`
- **총 학습일**: `StudyRecord` 의 distinct(answeredAt 날짜) 개수
- **총 푼 문장**: `StudyRecord` count
- **정답률(전체)**: `isCorrect=true` count / 전체 count
- **정답률(최근 7일)**: 최근 7일 범위 동일 계산
- **히트맵**: 날짜별 `StudyRecord` 건수 → 농도 단계화
- **복습 대기**: `ReviewItem` where `nextReviewAt <= 현재` count

### 복습 큐 망각곡선 (구체 수치)
| level | 다음 복습까지 | 정답 시 | 오답 시 |
|---|---|---|---|
| 0 | +1일 | level 1 로 | level 0 유지 |
| 1 | +3일 | level 2 로 | level 0 로 |
| 2 | +7일 | level 3 로 | level 0 로 |
| 3 | +30일 | level 3 유지(마스터) | level 0 로 |

### 상태별 화면
- **빈 상태**: 학습 기록 0 → "첫 학습을 시작해보세요" + 문장 해석 바로가기
- **로딩**: 집계 중 스켈레톤
- **데이터 출처**: STAGE C 까지 `localStorage` 집계 / P3 이후 `StudyRecord` 서버 집계

### 엣지 케이스
- 학습 기록 없음 → 모든 수치 0, 차트 빈 상태
- 스트릭 끊김 (어제 학습 안 함) → 다음 학습 시 `currentStreak` 1 로 리셋, `longestStreak` 는 보존
- **레벨 시스템 제거** — "레벨 N 학습자" 하드코딩 삭제. 배지·순위도 이번 범위 제외

## DB 스키마 영향 (Architecture-v2.md 와 동기화)

`User` 모델:
```prisma
model User {
  id            String   @id            // Supabase auth user uid
  username      String   @unique        // 로그인 ID (email → username 변경)
  displayName   String
  recoveryEmail String?                 // 선택 입력 — 비번 복구용
  phone         String?                 // 선택 입력 — 저장만 (SMS 활용은 유료 전환 시)
  carrier       String?                 // 선택 입력 — 저장만
  createdAt     DateTime @default(now())
  // 관계: loginLogs, sessions, records, reviewItems, streak, settings
}
```

`UserSettings.difficulty` — 최초 로그인 시 설정. 나머지 모델은 Architecture-v2.md 와 동일.

## 무과금 제약 하의 한계 (정직한 고지)

| 항목 | 가능 | 불가 (유료) |
|---|---|---|
| 비번 재설정 이메일 | Supabase 기본 SMTP, 무료 한도 내 가능 | — |
| 전화번호 SMS 인증/발송 | 필드 저장만 | Twilio 등 유료 — 미구현 |
| 통신사 본인확인 | 필드 저장만 | 본인인증기관 연동 유료 — 미구현 |

전화번호·통신사는 **데이터를 미리 쌓아두는 목적**이며, 실제 활용 기능은 유료 전환 시점으로 미룬다.
