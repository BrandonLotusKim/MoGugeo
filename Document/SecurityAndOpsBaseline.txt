============================================================
📌 보안 및 운영 기준선
============================================================

1. 비밀정보 관리
- 환경 변수는 코드 저장소에 직접 커밋하지 않는다.
- 운영용 비밀번호와 토큰은 문서 파일에 평문으로 저장하지 않는다.
- 비밀정보는 비밀번호 관리자 또는 별도 보안 저장소에서 관리한다.

2. DB 비밀번호 정책
- 운영 DB 비밀번호는 길고 추측 불가능한 값으로 만든다.
- 개발용과 운영용 비밀번호를 분리한다.
- 비밀번호를 메신저 대화에 직접 남기지 않는다.

3. 백업 정책
- 운영 DB는 자동 백업 기능을 사용한다.
- 최소 백업 확인 주기는 주 1회로 둔다.
- 장애 시 복구 가능한 최근 백업 존재 여부를 확인한다.

4. 운영 책임
- 설치 파일 업로드 담당자: 프로젝트 소유자
- 운영 배포 담당자: 프로젝트 소유자
- 관리자 계정 관리 담당자: 프로젝트 소유자

5. 장애 대응 최소 절차
- 다운로드 오류 발생 시 Spaces 링크 확인
- 웹 접속 장애 발생 시 App Platform 배포 상태 확인
- 데이터 문제 발생 시 PostgreSQL 상태와 최근 백업 확인
- 심각한 장애 시 다운로드 페이지에 임시 공지 게시

6. 계정 보안
- GitHub와 DigitalOcean 계정 모두 2FA 활성화
- 운영용 관리자 이메일을 개인 메인 이메일과 분리하는 것을 권장
